# helm — generated, then owned

Spartan primitives generated by `@spartan-ng/cli` and **owned by this library**
(`@lore/ui`), ported from `lore-dam` and `lore-inventory` so both apps share one
styled layer. Plan: `plans/120-design-system-components.md` (D2/D3).

- Brain (`@spartan-ng/brain`, node_modules) is **rented behavior** — never patch it.
- Helm (these files) is **our appearance** — edit freely.
- Components now live in this library, one ng-packagr secondary entry per
  primitive (`projects/ui/helm/<primitive>/`). Import as
  `@lore/ui/helm/<primitive>`. New primitives are generated with
  `@spartan-ng/cli` in a consuming app's scratch tree and ported here by hand —
  the CLI does not write into this workspace, and its tsconfig-path maintenance
  does not apply here (the `@lore/ui/helm/*` path map in `tsconfig.json` covers
  every entry).
- **Never rename generated `hlm*`/`brn*` selectors or class names.** Some primitives
  (select especially) break on selector rename. We edit class strings and templates,
  not identities.

## Restyle checklist (run this on every newly generated primitive)

1. **Semantic utilities only.** `bg-popover`, `text-muted-foreground`, `border-border`,
   `ring-ring`, `bg-destructive` — never raw palette (`bg-zinc-900`). These already
   resolve to lore's tokens through the hlm preset's `@theme inline`, so most colour
   needs zero edits. `@lore/ui/testing`'s token contract is the check.
2. **Density metrics.** Generated helm hard-codes `h-8` / `text-sm`. Rewrite control
   metrics onto the density tokens so `data-density` retunes helm like `.lore-ctl`:
   - height → `h-(--control-h-sm|md|lg)`
   - font-size → `text-(length:--text-ui-sm|md|lg)`
   - spacing → `px-[calc(var(--space)*N)]`, `gap-[calc(var(--space)*N)]`
3. **Motion tokens.** Transition/animation durations → `duration-(--motion-fast)` or
   `duration-(--motion-base)`. Anything animated must respect reduced motion —
   prefer the `motion-safe:` variant (helm often already does this).
4. **Radius: no work.** The preset derives `--radius-sm…4xl` from our base `--radius`.
5. **Shadow audit.** Shadow only on **transient layers** (menus, dialogs, popovers,
   drag previews). Elevation elsewhere = lighter surface + border.
6. **State via data variants.** Use the preset's `data-open:`, `data-checked:`,
   `data-disabled:`, `data-selected:` variants so visuals track the ARIA/data state
   brain maintains. Never strip `data-*`/`aria-*` from a helm template.
7. **Bridge rule.** If a helm template contains something that *is* a lore control
   (dialog/sheet close, tabs paginator, toast action), it takes `loreBtn` / `.lore-ctl`
   + matrix data attributes — **not** shadcn's `buttonVariants`. shadcn variant names
   (`default`/`destructive`/`outline`/`ghost`) must never reach lore's public API.
8. **Never `::ng-deep`** or global CSS against helm internals. These are owned files —
   edit them directly.

## Rulings

- **Target size (120 open question 4).** WCAG 2.2 (2.5.8) floor is 24×24 CSS px and it
  must hold in **compact** density, where `--control-h-sm` is itself exactly 24px.
  Any affordance whose *glyph* is smaller (checkbox at 16px, chip close, table row
  actions) expands its **pointer target** with padding or a `before:absolute
  before:-inset-*` bleed — never by growing the glyph. See `hlm-checkbox.ts`.
- **Two class idioms.** *Matrix* components (button, badge/chip) use `.lore-ctl` +
  `data-variant`/`data-color`/`data-size` styled in `theme/components.css`.
  *Structural/behavioral* helm (dialog frames, menu panels, tables) keeps the
  cva + `hlm()`/`classes()` + Tailwind idiom in these owned files.
- **`HlmTextarea` (`hlmTextarea`) is deprecated.** App code writes `<textarea hlmInput>`
  (`@lore/ui/helm/input`), which sits on `.lore-ctl` like every other control. The
  directive stays because `HlmInputGroupTextarea` hosts it and apps still import it;
  it takes `[aria-invalid]` the same way `HlmInput` does.
- **`HlmButton` (`hlmBtn`) is internal-only.** It exists because `input-group` (a
  dependency of `command`) needs it. App code uses `loreBtn` — the `LoreButton`
  directive, which lives beside it in `@lore/ui/helm/button` — never `hlmBtn`.

## Version note (spartan 1.1)

Helm 1.1 no longer builds host classes with `[class]="hlm(...)"` + `computed()`. It uses
the `classes(() => …)` host-class manager from `@lore/ui/helm/utils`, which merges
with the element's own `class` attribute via tailwind-merge (consumer `class` still
wins). Components that still take an explicit `class` input (e.g. `hlm-select-trigger`)
use `hlm()` + `computed()`. Match whichever idiom the file already uses.
